# I²C & PCA9685 — buses, addresses, pull-ups

Everything I²C-specific about the servo expanders: addressing, the two-bus
topology, and the pull-up rule that multi-board builds keep getting wrong.
Wire-by-wire connections are in [`wiring/WIRING.md`](wiring/WIRING.md); the
capacity limits (boards per bus, channels) are defined once in
[`README.md`](README.md) §Capacity.

## 1. Addressing

Each PCA9685 sets its address with the **A0–A2 solder jumpers**:
`0x40 + (A2·4 + A1·2 + A0)`, so **eight addresses per bus, 0x40…0x47**. Two
boards on the *same* bus must never share an address; the same address on the
*two different buses* is fine — a board's identity is **(bus, address)**, which
is exactly how the firmware and the web interface track it.

| Jumpers A2 A1 A0 | Address | Wizard's "PCA #n" |
| :--------------: | :-----: | :---------------: |
| 0 0 0 | 0x40 | #0 |
| 0 0 1 | 0x41 | #1 |
| … | … | … |
| 1 1 1 | 0x47 | #7 |

The web interface's wiring sheet shows each board's expected jumper setting —
set them **before** mounting the boards.

## 2. The two buses

The ESP32-S3 has two hardware I²C controllers. Bus 0 (`Wire`, pins `SDA`/`SCL`)
carries everything by default; large instruments can move boards to bus 1
(`Wire1`, pins `SDA2`/`SCL2`) to halve the traffic per bus and refresh servos
faster. Each bus has its own 0x40–0x47 range → up to **16 boards / 256
channels** total.

* Assign boards to buses in the Setup wizard (*Wiring & capacity*); the
  `SDA2`/`SCL2` pins then appear in *Wiring & GPIO*.
* Default second-bus pins come from the **board profile** — GPIO38/39 on an
  ESP32-S3-DevKitC-1 **v1.0**, GPIO39/42 on a **v1.1** (its RGB LED occupies
  GPIO38). There is deliberately no hard-coded fallback.
* The `/OE` safety line can stay shared across both buses or be split
  (`SERVO_OE2`) — see [`POWER_AND_SAFETY.md`](POWER_AND_SAFETY.md) §3.

## 3. Pull-ups: ONE equivalent value per bus

I²C is open-drain: each line needs a pull-up to 3.3 V. The mistake to avoid on
multi-board builds: **most PCA9685 breakouts ship their own pull-ups (usually
10 kΩ, some 4.7 kΩ), and pull-ups in parallel ADD**:

```text
PCA #0: 10 kΩ ∥ PCA #1: 10 kΩ ∥ PCA #2: 10 kΩ ∥ PCA #3: 10 kΩ  =  2.5 kΩ
8 boards with 4.7 kΩ each                                      ≈  590 Ω  ← too strong
```

Below roughly 1 kΩ the bus drivers can no longer pull the line reliably low
(the I²C spec floors around 3 mA sink at 3.3 V ≈ 1.1 kΩ); far above ~10 kΩ the
edges get too slow on a long harness. NXP's I²C design guidance sizes the
pull-up from the supply, sink current and bus capacitance — the practical rule
for this project:

> **Target one *equivalent* resistance of 2.2–4.7 kΩ per bus line** (SDA and
> SCL separately, per bus). Count every breakout's on-board resistors in that
> equivalent — do NOT add "a pair per PCA".

The web interface manages this budget live (*Wiring & GPIO → I²C & PCA*). Each
board starts as **unknown — not checked**: nothing is assumed until you have
looked at the breakout (schematic or multimeter) and declared what is fitted —
a value, or *none/removed*. With every board declared (plus any external pair)
the page computes the equivalent per line and grades it against the window; an
unchecked board keeps the bus at "cannot be verified".

Concretely:

* 1–2 boards with stock 10 kΩ pull-ups: usually fine as-is (10 kΩ or 5 kΩ
  equivalent) at 100 kHz; add one external 4.7 kΩ pair if edges look lazy.
* 3–4 boards: stock pull-ups alone land near 2.5–3.3 kΩ — good; add nothing.
* 5+ boards: **desolder/disable the pull-ups on all but one board** (or all,
  plus one external 2.2–4.7 kΩ pair per line at the ESP32 end), or the
  equivalent drops too low.
* The two buses are independent: each needs its own equivalent, on its own
  SDA/SCL pair.
* Keep the I²C harness short and away from servo leads; the bus runs at the
  default 100 kHz (400 kHz possible with a clean, short bus).

## 4. Health & degraded mode

After arming, the firmware probes each board (bus + address). A board that
stops answering faults **only the strings it drives** (`readyDegraded`) and
MIDI re-allocates to the remaining strings; global panic only fires when no
playable string remains. So a per-branch fuse blowing (see
[`POWER_AND_SAFETY.md`](POWER_AND_SAFETY.md) §1) shows up as one degraded
string group, not a dead instrument — by design.
